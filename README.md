# Board（貴族のひそめごと）

「貴族のひそめごと」は、イラストカードをもとに、親が作ったワードを子が見抜く、会話型の対人カードゲームです。

副題：見抜くか、欺くか。社交場の言葉遊び

## コンセプト

カードには、ひとつのボケとして成立する奇妙な情景が描かれています。

親はカードを見て、そのボケに対する新しいワードを1つ作ります。システムはカードに登録済みの公式ワードから3個を選び、親ワードと合わせた4個をシャッフルして公開します。

子は会話や親への質問を通じて、4つの候補から親ワードを推理します。

## 用語

- 親：カードを引き、親ワードを作成するプレイヤー
- 子：親が作成した親ワードを当てるプレイヤー
- カード：イラストと公式ワードが登録されたカード
- 公式ワード：カードにあらかじめ登録されたワード
- 親ワード：親がカードのイラストを見て新たに作成するワード

## ゲームルール

### 1ラウンドの流れ

1. 伏せ札の山からカードを1枚引きます。
2. 既に知っているカードだった場合は、カードを山札へ戻さずに「別の札を引く」を選び、ひとつ手前のCARD DRAW画面から別の札を引きます。
2. カードのイラストを全員に公開します。
3. カードに登録された公式ワードから、システムがランダムに3個を選びます。
4. 親にスマートフォンを渡します。
5. 親の本人確認後、親はカード画像と公式ワード3個を確認します。
6. 親はイラストに対する親ワードを1つ入力し、「ひそめる」を押します。
7. 公式ワード3個と親ワード1個、合計4個を自動でシャッフルします。
8. 「推理を開始」を押すと、言葉のお披露目から宴の推理へ移り、2分間のカウントダウンが始まります。
9. 2分間、全員で会話しながら推理します。
10. 時間終了後、各子は親ワードだと思う候補を1つ選びます。
11. 全員の回答後、「ひそめごと開帳」を押します。
12. 親ワード、正解者、不正解者、得点結果を表示します。
13. 親を交代して次の席へ進みます。

### 推理中のルール

- 子は親に質問できます。
- 親は質問に答えられます。
- 親は親ワードを直接明かしてはいけません。
- 各ラウンド画面の右上にある「退出」から、ゲームを終了してタイトル画面へ戻れます。
- ひそめごと開帳まで、親ワードと正誤判定は表示しません。

### 得点

| 結果 | 正解した子 | 親 |\n|---|---:|---:|\n| 一部の子だけ正解 | 正解者に＋1 | 0 |\n| 全員正解 | 全員に＋1 | −1 |\n| 全員不正解 | 0 | ＋1 |\n\n2人対戦では子が1人になるため、親に対する「全員正解時の−1ポイント」「全員不正解時の＋1ポイント」は適用しません。\n\n| 2人対戦の結果 | 子 | 親 |\n|---|---:|---:|\n| 子が正解 | ＋1 | 0 |\n| 子が不正解 | 0 | 0 |

画面上の結果表示は以下に統一します。

- 全員不正解：`全員不正解。親プラス1ポイント`
- 全員正解：`全員正解。子プラス1ポイント、親マイナス1ポイント`
- 一部の子が正解：`正解した子に1ポイント`

### 勝利条件

先に5ポイントへ到達したプレイヤーを勝利者とします。

同じラウンドで複数人が5ポイント以上に到達した場合は、複数人の勝利として扱います。同点時の最終的な勝敗決定方法は後で追加します。

### プレイヤー登録と親順

- プレイヤー人数は2〜6人です。
- 人数分のプレイヤー名を入力します。
- 空欄の名前と、同じ名前の重複登録はできません。
- 登録した名前は同じ端末のブラウザに保存し、再読み込み後も復元します。
- 保存した名前は対戦人数にかかわらず、一人目・二人目など同じ番号の入力欄へ復元します。人数を増やした場合は、保存されていない追加欄だけ空欄になります。
- 保存されていない入力欄は、初期値として「客人1」〜「客人6」を表示します。
- 最初の親はランダムに決定します。
- 以後は決定した順番で親を交代します。
- 各操作前に、現在スマートフォンを操作するプレイヤーの本人確認を行います。

## カード制作方針

- カード画像は、縦1536ピクセル、横1024ピクセルで制作します。
- カードはトランプのような縦長の比率にします。
- 豪華な装飾枠を設けます。
- 画像キャンバス全体を、一枚の完成したカード面として構成します。
- カードが白い背景や余白の中に浮かんでいるような構図にはしません。
- 外側の装飾枠の外側に、白色・無地・未描画の余白を作りません。
- 背景、装飾枠、情景を含むカード全体で、1536×1024ピクセルの画面を隙間なく使用します。
- 一枚のカードを画面内に配置したような表現ではなく、画面全体が最初から一枚のカードとして成立するように描きます。
- 中央には、ひとつのボケとして成立する奇妙な情景を描きます。
- イラストは、少し毒気のある風刺画・カーニバルポスター風のタッチで統一します。
- カード内に文字やロゴは入れません。
- 題材や発想の型を偏らせません。
- 合体的な絵だけに偏らず、競技、職業、行事、日常の誇張、動物、建物、道具、風景、失敗や勘違いなどを混ぜます。
- カードを見た時点で、プレイヤーがツッコミや解釈を考えたくなる情景を目指します。
- 画面全体の明度や色調は、題材や情景に合わせて変化させます。
- 作品ごとに明るい配色・暗い配色のどちらも許容し、毎回同じ方向へ寄せません。
- ただし、暗い配色の場合も、主役や情景の細部が見分けられるようにします。

## 公式ワード制作方針

公式ワードは、カードのイラストを確認したうえで、その情景に対する反応として作成します。

各カードには、ゲーム内で使用する公式ワードを10個以上登録します。

### 作成ルール

公式ワードは、カードの情景を見たときの反応として作成します。単なる物の名前や情景説明だけで終わらせず、次のような形式・発想を同じカード内で混在させます。

- 情景への一言ツッコミ、ノリツッコミ、例えツッコミ
- 登場人物が言いそうなセリフや会話の一部
- 勘違い・失敗・別の出来事に置き換えた解釈
- 商品名・企画名・競技名・ニュース見出しのような表現
- ことわざ・慣用句・有名作品などをもじった表現
- 駄洒落、造語、意外な組み合わせ
- イラストから連想を広げた別の物語や状況
- 描かれた情景への疑問やツッコミ

10個すべてを同じ文型にせず、笑いの生まれ方と発想の方向を分散させます。特に「○○した結果」「○○の末路」「○○が○○している」「○○すぎる」「○○を間違えた」といった型だけを繰り返しません。

### イラストとの整合性

公式ワードは、イラストに明らかに描かれている内容と矛盾しないようにします。

ワードを作成するときは、次のような要素をイラスト上で確認します。

- 物体の種類
- 人物や動物の種類
- 物体の状態
- 開いているか、閉じているか
- 濡れているか、乾いているか
- 色や形
- 数
- 大きさ
- 位置関係
- 持っている物、身につけている物
- 表情や動作

イラストに描かれていない部分を想像した内容や、見えない事情への妄想、疑問形、これから起こることへの予想は、イラストに明らかに反しない限り使用できます。

一方で、イラストに描かれている物体・人物・動物・状態・位置関係などを、実際とは別のものとして断定する表現は避けます。

例えば、イラストにカバンが描かれている場合、それを封筒や別の道具として断定する表現は使用しません。

### 分かりやすさと自然さ

子どもでも意味を理解しやすく、親がその場で作ったワードとして自然に見える表現にします。少し難しい言葉や固有名詞も、ワード全体の意味が伝わり、カードのボケへの反応として成立していれば使用できます。

次のようなワードは避けます。

- 意味を理解するために長い説明が必要なもの
- 単独では意味が伝わりにくい単語だけのもの
- 親がその場で作ったワードとして不自然なもの
- カードの情景との関係が薄いもの
- イラストに明らかに反するもの
- 他の公式ワードと意味や構造がほぼ同じもの

発想の奇抜さだけでなく、ゲーム中に見たときの分かりやすさと、親ワードに紛れ込める自然さを重視します。

### 登録前の確認

公式ワードを登録する前に、カード画像とワードを一つずつ照合します。

- 公式ワードが10個以上あること
- ツッコミ、セリフ、例え、見出し、別解釈などの形式が混在していること
- 同じ文型や発想に偏っていないこと
- 見たままの説明だけで終わっていないこと
- 子どもでも意味を理解しやすいこと
- 親がその場で作ったワードとして自然に見えること
- イラストに明らかに反する内容がないこと
- 物体・人物・動物の種類を取り違えていないこと
- 状態や位置関係を、イラストと逆に断定していないこと
- 他のワードと意味や構造が重複していないこと

この確認では、イラストに描かれていない部分を想像していることだけを理由にNGとはしません。

NGとするのは、イラストに明らかに描かれている内容と異なる場合です。

例えば、次のような表現はNGです。

- 閉じている物を「開いている」と断定する
- 乾いている物を「濡れている」と断定する
- カバンを「封筒」と断定する
- 描かれている人物や動物を、別の種類として断定する
- 実際とは異なる位置関係を断定する

一方で、次のような表現は、イラストと矛盾しなければ使用できます。

- 描かれていない部分への想像
- 見えない事情への妄想
- これから起こることへの予想
- イラストに対する疑問
- 情景へのツッコミ
- 実際には確認できない裏側や後日談

例：

- イラスト：リンゴに鴨が刺さっている
- 公式ワード：`リンガモ`、`カモネギのリンゴバージョン`、`ウィリアム・テルが間違えたんか`、`ピコ太郎`

## カードデータ

カードセットごとに `cards/<カードセットID>/cards.json` で管理します。

現在の構成は以下です。

```text
cards/
├── test/
│   ├── cards.json
│   └── カード画像
└── vol1/
    ├── cards.json
    └── カード画像
```

- `test`：画面上では「お試し版」と表示するカードセットです。
- `vol1`：画面上では「VOL.1」と表示するカードセットです。
- 各 `cards.json` は、カードセット名・カード一覧・ワードセット一覧を保持します。
- 人数選択画面では、カードセットをリストから選び、選択したカードセットに対応するワードセットを別のリストから選びます。
- カードセットの初期選択は `VOL.1` です。
- カードセットと、カードセットごとのワードセット選択は、次回起動時にも復元します。

```json
{
  "id": "vol1",
  "name": "VOL.1",
  "cards": [
    {
      "id": 1,
      "image": "カード画像ファイル名"
    }
  ],
  "wordSets": [
    {
      "id": "standard-1",
      "name": "標準セット",
      "cards": [
        {
          "cardId": 1,
          "officialWords": [
            "公式ワード1",
            "公式ワード2",
            "公式ワード3"
          ]
        }
      ]
    }
  ]
}
```

- `cards` にはカードIDと画像ファイル名を登録します。
- `wordSets` には、同じカードセットで使用するワードセットを登録します。
- `wordSets[].cards[].cardId` で画像カードと公式ワードを対応づけます。
- 公式ワードは各カードにつき10個以上を登録し、各ラウンドで重複なく3個を選びます。
- 同じカードは、同一ゲーム内で重複して使用しません。
- カード画像と `cards.json` は、同じカードセットのフォルダで管理します。
- 画像ファイル名と `cards.json` の `image` 指定を一致させます。
- カード画像は正常なPNG形式で登録します。
- 新しいワードセットを追加すると、同じカード画像で別の公式ワード群を使用できます。
- ワードセットを追加する場合は、対象カードセットの `cards.json` に `wordSets` を追加します。選択画面は登録済みの `wordSets` から選択肢を自動生成するため、通常はHTMLやJavaScriptの変更は不要です。

## カード追加・公開手順

新しいカードを追加する際は、以下の手順で進めます。

1. 新規カードのイラストを確認し、カードの情景に対する公式ワードを10個以上作成します。
2. 作成した公式ワードをカード画像と一つずつ照合し、イラストに明らかに反する内容や、物体・人物・動物・状態の取り違えがないことを確認します。
3. 描かれていない部分への想像や疑問、ツッコミは、イラストと明らかに矛盾しない限り使用できます。
4. 既存カードと題材・発想・公式ワードの切り口が偏らないことを確認します。
5. 追加するカードには、既存の続き番号を付けます。
6. カード画像の作成時にカード番号の指定がある場合は、ライブラリ保存時点からGitHubへアップロードする最終ファイル名を付けます。例：11枚目の「雲を刈る床屋」は `card-011-cloud-barber.png`。
7. カード画像は、横1024×縦1536ピクセルの正常なPNGとして作成します。
8. カード画像は、`cards.json` の `image` と完全に同じファイル名でライブラリに保存します。
9. `cards.json` に、カードID・画像ファイル名・公式ワードを追加します。
10. カード画像は、GitHubの画面から手動で `cards/<バージョン名>/` へアップロードします。既存カードの差し替えでは、同名の画像ファイルを置き換えます。
11. アップロード後、GitHub上で以下を確認します。
   - 画像ファイル名と `cards.json` の `image` 指定が一致していること
   - 全画像が正常なPNGとして開けること
   - 画像サイズが横1024×縦1536ピクセルであること
   - `officialWords` が各カード10個以上あること
   - GitHub Pages上でもカード画像を読み込めること
12. 上記をすべて確認できるまで、追加作業を完了扱いにしません。

カード画像は、GitHubへ登録する際に画像変換・圧縮を行わず、作成済みのPNGデータをそのまま使用します。

## 現在の実装

現在は、1台のスマートフォンを順番に操作して遊ぶローカル版です。

実装済みの主な機能：

- プレイヤー人数の登録（2〜6人）、選択人数の保存と次回表示時の復元
- カードセット選択の保存と次回表示時の復元
- カードセットごとのワードセット選択の保存と次回表示時の復元
- プレイヤー名の入力、対戦人数に依存しない保存・復元
- 空欄・重複名のチェック
- 親順の初回ランダム決定と以後の固定順交代
- 各操作前の本人確認
- カードのランダム表示と重複使用防止
- 公式ワード3個のランダム選択
- 親ワードの入力
- 4ワードのシャッフル
- 言葉のお披露目から宴の推理への遷移と2分間のカウントダウン
- 各ラウンド画面からの「退出」とタイトル画面への復帰
- 子による回答入力
- 子の回答順は、親の直後の席から席順を一周する順番
- 回答者名と選択候補の表示
- 回答開示前の親ワード非表示
- 正解判定と得点処理（2人対戦では親の全員正解・全員不正解による増減なし）
- ひそめごと開帳時のワード順番確認演出と親ワード発見演出
- 5ポイント到達者の表示
- 次ラウンドへの移行
- ゲーム中の各画面でのカード画像表示
- ROUND CARD DRAW画面の親の名前を大きく表示
- CARD OPEN画面でカード表示領域を先に確保し、画像読み込み時のレイアウト移動を防止\n- CARD OPEN画面で既知のカードを山札へ戻さずに「別の札を引く」ことが可能\n- 別の札を引く時はひとつ手前のCARD DRAW画面へ戻り、そこから新しい伏せ札を引く\n- CARD OPEN画面の「確認」・「別の札を引く」ボタンを従来のボタンサイズで横並びに表示
- 絵柄が表示されるカードをタップまたはキーボード操作で拡大表示
- カード拡大表示は画面の表示領域内にカード全体を収め、画像を切り取らない
- 拡大表示の閉じるボタンは画面右上に固定し、十分なタップ領域を確保する
- 拡大表示は閉じるボタン、カード外タップ、Escキーで終了
- 画像読み込み失敗時のエラー表示
- 進行ボタンを画面幅いっぱい・高さ52pxで統一し、戻る系ボタンも同じ高さで表示
- 左右に2つのボタンがある画面では、左に戻る・別の札を引く・キャンセル、右に確定・開始・次へ進むボタンを均等幅で表示
- CARD OPEN画面は左に「別の札を引く」、右に「確認」を均等幅で表示
- 各ラウンド画面の「退出」をタイトルと同じ行の右端に表示
- UTF-8による日本語表示
- 画面外周と画面内の不要な余白を抑えたスマートフォン向けレイアウト
- `test` にお試し版カードの登録
- `vol1` にVOL.1カードの登録
- カードセットとワードセットのリスト選択

### ひそめごと開帳の演出

「ひそめごと開帳」を押すまでは、4つのワードを同じ見た目で表示します。押した後は、正解色が4つのワードの間を360ms間隔で3周します。その後、次の周回で親ワードに到達し、親ワードの位置で180ms間隔の点滅を5回行って停止します。演出が完了するまで「得点を確認」は押せません。

## 開発方針

- ブラウザ上で遊べるゲームとして制作します。
- まずは1台のスマートフォンで遊べるローカルゲームを完成させます。
- カード画像と公式ワードは事前に作成して登録します。
- ゲーム中にAIでイラストや公式ワードを生成する機能は実装しません。
- ソースコードはGitHubで管理します。
- 修正時は既存機能を壊さないよう確認してから変更します。
- カード画像はテキストとして扱わず、正常なバイナリPNGとして登録します。
- 画像を追加・差し替える際は、公開前にPNG/JPEGとして読み込める有効な画像ファイルであることを確認します。拡張子だけが画像形式に見える壊れたデータは登録しません。
- 画像URLには、キャッシュ更新のための`?v=`などのバージョン表記を付けません。画像の差し替え後は、GitHub Pagesの公開反映を確認します。
- GitHubへ反映後は、公開URLでHTML、JavaScript、`cards.json`、カード画像の読み込みを確認します。
- 画像、CSS、JavaScriptを含むすべての公開URLに、キャッシュ更新のための`?v=`などのバージョン表記を付けません。GitHub Pagesの公開反映を確認してから、通常の再読み込みで確認します。
- キャッシュ番号の更新を目的としたGitHub Actionsや、自動コミット・自動pushの仕組みは使用しません。
