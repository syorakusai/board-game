# Board（貴族のひそめごと）

「貴族のひそめごと」は、イラストカードをもとに、親が作ったワードを子が見抜く、会話型の対人カードゲームです。

副題：見抜くか、欺くか。社交場の言葉遊び

## コンセプト

カードには、ひとつのボケとして成立する奇妙な情景が描かれています。

親はカードを見て、そのボケに対する新しいワードを1つ作ります。システムはカードに登録済みの公式ワードから3個を選び、親ワードと合わせた4個をシャッフルして公開します。

子は会話や親への質問を通じて、4つの候補から親ワードを推理します。

## 用語

- 親：カードを引き、親ワードを作成するプレイヤー
- 子：親が作成した親ワードを当てるプレイヤー
- カード：イラストと公式ワードが登録されたカード
- 公式ワード：カードにあらかじめ登録されたワード
- 親ワード：親がカードのイラストを見て新たに作成するワード

## ゲームルール

### 1ラウンドの流れ

1. 伏せ札の山からカードを1枚引きます。
2. 既に知っているカードだった場合は、カードを山札へ戻さずに「別の札を引く」を選び、ひとつ手前のCARD DRAW画面から別の札を引きます。
2. カードのイラストを全員に公開します。
3. カードに登録された公式ワードから、システムがランダムに3個を選びます。
4. 親にスマートフォンを渡します。
5. 親の本人確認後、親はカード画像と公式ワード3個を確認します。
6. 親はイラストに対する親ワードを1つ入力し、「ひそめる」を押します。
7. 公式ワード3個と親ワード1個、合計4個を自動でシャッフルします。
8. 全員がワードを確認したら、「推理を始める」を押します。
9. 1分間、全員で会話しながら推理します。
10. 時間終了後、各子は親ワードだと思う候補を1つ選びます。
11. 全員の回答後、「ひそめごと開帳」を押します。
12. 親ワード、正解者、不正解者、得点結果を表示します。
13. 親を交代して次の席へ進みます。

### 推理中のルール

- 子は親に質問できます。
- 親は質問に答えられます。
- 親は親ワードを直接明かしてはいけません。
- 各ラウンド画面の右上にある「退出」から、ゲームを終了してタイトル画面へ戻れます。
- ひそめごと開帳まで、親ワードと正誤判定は表示しません。

### 得点

| 結果 | 正解した子 | 親 |\n|---|---:|---:|\n| 一部の子だけ正解 | 正解者に＋1 | 0 |\n| 全員正解 | 全員に＋1 | −1 |\n| 全員不正解 | 0 | ＋1 |\n\n2人対戦では子が1人になるため、親に対する「全員正解時の−1ポイント」「全員不正解時の＋1ポイント」は適用しません。\n\n| 2人対戦の結果 | 子 | 親 |\n|---|---:|---:|\n| 子が正解 | ＋1 | 0 |\n| 子が不正解 | 0 | 0 |

画面上の結果表示は以下に統一します。

- 全員不正解：`全員不正解。親プラス1ポイント`
- 全員正解：`全員正解。子プラス1ポイント、親マイナス1ポイント`
- 一部の子が正解：`正解した子に1ポイント`

### 勝利条件

先に5ポイントへ到達したプレイヤーを勝利者とします。

同じラウンドで複数人が5ポイント以上に到達した場合は、複数人の勝利として扱います。同点時の最終的な勝敗決定方法は後で追加します。

### プレイヤー登録と親順

- プレイヤー人数は2〜6人です。
- 人数分のプレイヤー名を入力します。
- 空欄の名前と、同じ名前の重複登録はできません。
- 登録した名前は同じ端末のブラウザに保存し、再読み込み後も復元します。
- 保存した名前は対戦人数にかかわらず、一人目・二人目など同じ番号の入力欄へ復元します。人数を増やした場合は、保存されていない追加欄だけ空欄になります。
- 保存されていない入力欄は、初期値として「客人1」〜「客人6」を表示します。
- 最初の親はランダムに決定します。
- 以後は決定した順番で親を交代します。
- 各操作前に、現在スマートフォンを操作するプレイヤーの本人確認を行います。

## カード制作方針

- カード画像は、縦1536ピクセル、横1024ピクセルで制作します。
- カードはトランプのような縦長の比率にします。
- 豪華な装飾枠を設けます。
- 中央には、ひとつのボケとして成立する奇妙な情景を描きます。
- イラストは、少し毒気のある風刺画・カーニバルポスター風のタッチで統一します。
- カード内に文字やロゴは入れません。
- 題材や発想の型を偏らせません。
- 合体的な絵だけに偏らず、競技、職業、行事、日常の誇張、動物、建物、道具、風景、失敗や勘違いなどを混ぜます。
- カードを見た時点で、プレイヤーがツッコミや解釈を考えたくなる情景を目指します。
- 画面全体の明度や色調は、題材や情景に合わせて変化させます。
- 作品ごとに明るい配色・暗い配色のどちらも許容し、毎回同じ方向へ寄せません。
- ただし、暗い配色の場合も、主役や情景の細部が見分けられるようにします。

## 公式ワード制作方針

- 新しいカードには、`officialWords` を10個以上登録します。
- 公式ワードは、カード内のボケに対する反応として作成します。
- 単なる物の名前や情景説明だけにしません。
- ツッコミ、解釈、連想、たとえ、駄洒落・造語、既存の言葉をもじった表現、有名人や作品への連想、勘違いや失敗に見立てた表現、短い一言コメントなどの切り口を混ぜます。
- 公式ワード同士が同じ型ばかりにならないよう、切り口を散らします。
- 親が作るワードに自然に紛れられる内容にします。
### ワードの分かりやすさ

公式ワードは、子どもでも意味を理解しやすく、親がその場で自然に思いつきそうな表現にします。

ただし、使われている言葉が少し難しいという理由だけで、機械的に除外することはありません。ワード全体の意味が伝わり、カードのボケに対する面白い反応になっていれば採用できます。

奇妙な発想、ギャグ、駄洒落、造語、意外な組み合わせなどは、これまでどおり積極的に使います。

#### OKの例

以下のように、少し特徴のある言葉を使っていても、意味が分かりやすく、ワードとして自然に成立しているものは使用できます。

- 在宅勤務の最終形態
- 鼻先のソムリエ
- 犬の品評会で下克上
- 生クリームの要塞
- 指揮棒を獲物だと思った猫
- 猿の学芸員
- 展示順に異議あり
- 計測係が一番まじめ
- 最終兵器
- アフタヌーンティー
- 美術館
- 模様替え

#### NGの例

以下のように、意味が伝わりにくい、日常的なワードとして使いにくい、または親がその場で自然に作ったように感じにくいものは避けます。

- 釣果
- 給仕
- 定刻を気にする最遅の駅員
- 司書の仕事量が見えない
- 猫の管弦楽団
- 海辺の大捕物
- これはもう帆船
- 管弦楽団
- 捕物
- 帆船
- 最遅
- 駅員帽

NGの例は、発想が面白くないからではありません。カードゲーム中に見たとき、意味を理解しにくかったり、親が自然に作ったワードとして受け入れにくかったりするため避けます。

例：

- イラスト：リンゴに鴨が刺さっている
- 公式ワード：`リンガモ`、`カモネギのリンゴバージョン`、`ウィリアム・テルが間違えたんか`、`ピコ太郎`

## カードデータ

カードはバージョンごとに `cards/<バージョン名>/cards.json` で管理します。

現在の構成は以下です。

```text
cards/
├── test/
│   ├── cards.json
│   └── card-001-apple-duck.png ～ card-015-museum-monkeys.png
└── vol1/
    ├── cards.json
    └── card-001-pigeon-maitre-d.png ～ card-020-octopus-pianos.png
```

- `test`：現在の15枚のテスト用カードです。
- `vol1`：第1弾のカード20枚です。
- 人数選択画面では、人数を選んだ下側で `テスト版` または `VOL.1` を選べます。
- 人数とカードセットを選択した後、「次へ」ボタンでプレイヤー名入力画面へ進みます。
- 人数・カードセット選択画面のタイトルは「宴の支度」です。
- プレイヤー名の登録後は、ランダムに決まった順番を「宴の席次」として表示します。
- プレイヤー名入力画面のタイトルは「客人の名乗り」とし、「客人の名前を入力してください。」と表示します。入力欄は「一人目」「二人目」などの表記にします。\n- プレイヤー名入力画面では、入力欄を表示しますが、初期表示時に名前欄へカーソルを移動せず、キーボードも自動表示しません。
- 初期選択は `VOL.1` です。

```json
{
  "id": 1,
  "image": "カード画像ファイル名",
  "officialWords": [
    "公式ワード1",
    "公式ワード2",
    "公式ワード3",
    "公式ワード4",
    "公式ワード5",
    "公式ワード6",
    "公式ワード7",
    "公式ワード8",
    "公式ワード9",
    "公式ワード10"
  ]
}
```

- `officialWords` には10個以上のワードを登録します。
- 各ラウンドで、登録された公式ワードから重複なくランダムに3個を選びます。
- 同じカードは、同一ゲーム内で重複して使用しません。
- カード画像と `cards.json` は、同じバージョンのフォルダで管理します。
- 画像ファイル名と `cards.json` の `image` 指定を一致させます。
- カード画像は正常なPNG形式で登録します。
- カードをすべて使用した場合の処理は後で追加します。


## カード追加・公開手順

新しいカードを追加する際は、以下の手順で進めます。

1. 新規カードのイラストと、各カードにつき10個以上の公式ワードを作成します。
2. 既存カードと題材・発想・公式ワードの切り口が偏らないことを確認します。
3. 追加するカードには、既存の続き番号を付けます。
4. カード画像の作成時にカード番号の指定がある場合は、ライブラリ保存時点からGitHubへアップロードする最終ファイル名を付けます。例：11枚目の「雲を刈る床屋」は `card-011-cloud-barber.png`。
5. カード画像は、横1024×縦1536ピクセルの正常なPNGとして作成します。
6. カード画像は、`cards.json` の `image` と完全に同じファイル名でライブラリに保存します。
7. `cards.json` に、カードID・画像ファイル名・公式ワードを追加します。
8. カード画像は、GitHubの画面から手動で `cards/<バージョン名>/` へアップロードします。既存カードの差し替えでは、同名の画像ファイルを置き換えます。
9. アップロード後、GitHub上で以下を確認します。
   - 画像ファイル名と `cards.json` の `image` 指定が一致していること
   - 全画像が正常なPNGとして開けること
   - 画像サイズが横1024×縦1536ピクセルであること
   - `officialWords` が各カード10個以上あること
   - GitHub Pages上でもカード画像を読み込めること
10. 上記をすべて確認できるまで、追加作業を完了扱いにしません。

カード画像は、GitHubへ登録する際に画像変換・圧縮を行わず、作成済みのPNGデータをそのまま使用します。

## 現在の実装

現在は、1台のスマートフォンを順番に操作して遊ぶローカル版です。

実装済みの主な機能：

- プレイヤー人数の登録（2〜6人）、選択人数の保存と次回表示時の復元
- カードセット選択の保存と次回表示時の復元
- プレイヤー名の入力、対戦人数に依存しない保存・復元
- 空欄・重複名のチェック
- 親順の初回ランダム決定と以後の固定順交代
- 各操作前の本人確認
- カードのランダム表示と重複使用防止
- 公式ワード3個のランダム選択
- 親ワードの入力
- 4ワードのシャッフル
- 推理開始ボタンと1分間のカウントダウン
- 各ラウンド画面からの「退出」とタイトル画面への復帰
- 子による回答入力
- 子の回答順は、親の直後の席から席順を一周する順番
- 回答者名と選択候補の表示
- 回答開示前の親ワード非表示
- 正解判定と得点処理（2人対戦では親の全員正解・全員不正解による増減なし）
- ひそめごと開帳時のワード順番確認演出と親ワード発見演出
- 5ポイント到達者の表示
- 次ラウンドへの移行
- ゲーム中の各画面でのカード画像表示
- ROUND CARD DRAW画面の親の名前を大きく表示
- CARD OPEN画面でカード表示領域を先に確保し、画像読み込み時のレイアウト移動を防止\n- CARD OPEN画面で既知のカードを山札へ戻さずに「別の札を引く」ことが可能\n- 別の札を引く時はひとつ手前のCARD DRAW画面へ戻り、そこから新しい伏せ札を引く\n- CARD OPEN画面の「確認」・「別の札を引く」ボタンを従来のボタンサイズで横並びに表示
- 絵柄が表示されるカードをタップまたはキーボード操作で拡大表示
- カード拡大表示は画面の表示領域内にカード全体を収め、画像を切り取らない
- 拡大表示の閉じるボタンは画面右上に固定し、十分なタップ領域を確保する
- 拡大表示は閉じるボタン、カード外タップ、Escキーで終了
- 画像読み込み失敗時のエラー表示
- 進行ボタンを画面幅いっぱい・高さ52pxで統一し、戻る系ボタンも同じ高さで表示
- 左右に2つのボタンがある画面では、左に戻る・別の札を引く・キャンセル、右に確定・開始・次へ進むボタンを均等幅で表示
- CARD OPEN画面は左に「別の札を引く」、右に「確認」を均等幅で表示
- 各ラウンド画面の「退出」をタイトルと同じ行の右端に表示
- UTF-8による日本語表示
- 画面外周と画面内の不要な余白を抑えたスマートフォン向けレイアウト
- `test` にテスト用カード15枚の登録
- `vol1` に第1弾カード10枚の登録

### ひそめごと開帳の演出

「ひそめごと開帳」を押すまでは、4つのワードを同じ見た目で表示します。押した後は、正解色が4つのワードの間を360ms間隔で3周します。その後、次の周回で親ワードに到達し、親ワードの位置で180ms間隔の点滅を5回行って停止します。演出が完了するまで「得点を確認」は押せません。

## 開発方針

- ブラウザ上で遊べるゲームとして制作します。
- まずは1台のスマートフォンで遊べるローカルゲームを完成させます。
- カード画像と公式ワードは事前に作成して登録します。
- ゲーム中にAIでイラストや公式ワードを生成する機能は実装しません。
- ソースコードはGitHubで管理します。
- 修正時は既存機能を壊さないよう確認してから変更します。
- カード画像はテキストとして扱わず、正常なバイナリPNGとして登録します。
- GitHubへ反映後は、公開URLでHTML、JavaScript、`cards.json`、カード画像の読み込みを確認します。
- 将来的な複数端末によるオンライン対戦への拡張を考慮します。
