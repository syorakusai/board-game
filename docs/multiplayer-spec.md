# 通信対戦仕様書

最終更新日：2026-08-14

この文書を通信対戦の切断・復帰・退出・宴終了仕様の正本とします。通信対戦を実装・変更する前に必ず確認し、仕様変更時はコードと同じコミットで更新します。

## 1. 用語

- **主催者**：通信対戦の部屋を作成したプレイヤー（ホスト）
- **参加者**：部屋番号・招待URL・QRコードから入室したプレイヤー（ゲスト）
- **親**：各ラウンドでカードを引き、親ワードを作成するゲーム内の役割
- **子**：各ラウンドで親ワードを推理するゲーム内の役割
- **切断**：再読み込み、ブラウザ・PWA終了、一時的な通信断など、明示的な退出を伴わない接続喪失
- **退出**：本人が右上メニューまたは復帰確認画面から明示的に宴を離れる操作

Firebaseがサーバーで、主催者・参加者の各端末はいずれもクライアントです。通信上の役割に「親・子」や「サーバー・クライアント」を使いません。

## 2. 基本方針

- 主催者と参加者の復帰方法は共通です。
- 切断と退出を分け、切断だけでは参加情報や宴を削除しません。
- 誰かが切断したら、時間制限なしで復帰を待ち、その間は全員のゲーム進行を停止します。
- 切断者が復帰したら、中断前と同じ宴・同じ進行状態から再開します。
- 誰か1人でも明示的に退出したら、その宴は終了します。
- 切断者を除外した続行、残り人数による続行、主催者移譲は実装しません。

## 3. 名前パネルとメッセージバー

### 待機室

- 名前パネルとメッセージバーは表示しません。
- 「客人が揃うのを待っています」などをメッセージバーへ表示しません。
- 待機室の参加者一覧と入退室は、待機室固有の画面で扱います。

### ラウンド開始後

- 最初のラウンド画面から、名前パネルと直下のメッセージバーを画面上部へ固定表示します。
- ラウンド画面の見出し・戦績・右上メニュー・本文は固定領域の下から始め、重ねません。
- メッセージバーは1行表示とし、短い文言は静止表示します。
- 文言が表示幅を超える場合だけ、救済措置として右から左へ自動スクロールします。
- 通常時は現在の進行状況を表示します。
- 正式な文言は各ラウンド画面の実装時に確定します。

文言例（未確定）：`親が札を選んでいます`、`宴の推理中です`、`客人の回答を待っています`

## 4. 切断中

残っているプレイヤーの画面：

- 現在のラウンド画面を維持します。
- 回答、決定、次画面への遷移など、ゲームを進める操作を停止します。
- メッセージバーに切断者と復帰待ちであることを表示します。
- 復帰待ちの時間制限は設けません。
- 右上メニューの退出は利用できます。

文言例（未確定）：

- 1人：`○○が切断中。復帰待ち`
- 複数人：`○○、△△が切断中。復帰待ち`

## 5. 切断者の復帰

端末へ少なくとも以下を保存します。

- 部屋番号
- Firebase UID
- プレイヤー名
- 通信上の役割（主催者／参加者）
- 参加していた宴の識別情報

再起動時はタイトル画面へ進む前に、Firebaseで以下を確認します。

- 部屋が存在すること
- 宴が復帰可能、または終了済み画面を復元可能であること
- 同じUIDの参加情報が残っていること
- 保存した主催者／参加者の役割がFirebase上の情報と一致すること

復帰可能な場合の選択肢：

- `宴に復帰する`
- `宴から退出する`

`タイトルへ進む`は設けません。参加状態を残したまま別の宴を開始する状態を作らないためです。

復帰成功時：

- 本人をオンラインへ戻します。
- Firebaseの進行状態から中断前の画面を復元します。
- 他端末の切断表示を解除します。
- 全員がオンラインへ戻ったらゲーム進行を再開します。
- メッセージバーを通常表示へ戻します。

状態確認に失敗した場合：

- 部屋が削除・終了したとは判断しません。
- 端末の復帰情報を削除しません。
- `もう一度確認する`を表示します。
- 閉じても復帰情報を保持し、次回起動時に再確認します。

## 6. 明示的な退出

接続中の右上メニューからの退出と、復帰確認画面からの退出は同じ意味です。

- 退出前に「退出すると全員の宴が終了する」ことを確認します。
- 退出確定後、本人の退出情報をFirebaseへ記録します。
- 本人の端末から復帰情報を削除します。
- 退出した本人は通信対戦画面へ戻ります。
- 宴を終了状態とし、残っている全員へ通知します。

確認文言例（未確定）：

`退出すると、この宴は全員終了となります。退出しますか？`

## 7. 宴終了後の残存画面

誰かが退出しても、残っている人を通信対戦画面へ自動遷移させません。

- 現在のラウンド画面、名前パネル、得点を維持します。
- メッセージバーへ終了理由と各自の退出案内を表示します。
- ゲームを進める操作は無効化します。
- 戦績、メニュー、遊び方、カード拡大など、振り返りに必要な閲覧操作は利用できます。
- 各自が確認後、右上メニューの退出から通信対戦画面へ戻ります。
- 同時退出時は、最初に記録された退出者を終了理由として表示します。

文言例（未確定）：

`○○が退出したため、宴はお開きとなります。右上メニューの「退出」から退出してください。`

| 操作 | 宴終了後 |
|---|---|
| 戦績・メニュー・遊び方 | 利用可 |
| カードの拡大・確認 | 利用可 |
| 回答・決定 | 利用不可 |
| 次画面・次ラウンドへの進行 | 利用不可 |
| 退出 | 利用可 |

## 8. 切断中に宴が終了した場合

切断中に別のプレイヤーが退出した場合、次回起動時に通信対戦画面へ直接戻しません。

- 終了した宴のラウンド画面を復元します。
- 終了メッセージを表示します。
- 戦績・遊び方・カードなどを確認できます。
- ゲーム進行はできません。
- 本人が右上メニューから退出した後、復帰情報を削除して通信対戦画面へ戻ります。

## 9. メッセージバーの優先順位

1. 宴終了
2. 切断中
3. 通常の進行状況

正式文言は各画面の実装時に確定します。

## 10. 復元する進行状態

端末内の画面番号だけに依存せず、Firebase上の宴状態を正本とします。少なくとも以下を段階的に同期します。

- ラウンド番号、現在工程、席順、現在の親
- 使用中カード、公式ワード、親ワード、公開4ワードと表示順
- 回答状況・回答、得点、戦績
- 宴終了状態と退出者
- 各プレイヤーの接続状態

秘密情報は、その工程で閲覧権限がある端末だけに表示します。具体的なデータ構造とルールは実装前に確定します。

## 11. 実装順序

1. 復帰基盤：端末保存、接続状態、切断と退出の区別、現在完成している札選びまでの復帰
2. 1ラウンドの正常系を最後まで完成
3. 各工程をFirebase状態から復元
4. 全ラウンド画面へ切断中の停止とメッセージバーを適用
5. 確定したデータ構造に合わせてFirebaseルールを更新

## 12. Firebaseルール

具体的なルール全文は未確定です。データ構造確定後、少なくとも以下を満たす全文を提示・更新します。

- 各自が自分の接続状態と退出意思だけを更新できる
- 参加者が部屋設定や他人の情報を変更できない
- 誰かの退出による宴終了を全端末が確認できる
- 主催者不在でも、参加者本人の正当な退出記録が残る
- 秘密情報を権限のない端末へ公開しない
- 不正な画面進行や他人の回答・得点変更を防ぐ
