# 通信対戦仕様書

最終更新日：2026-08-20

この文書を通信対戦の切断・復帰・退出・宴終了仕様の正本とします。通信対戦を実装・変更する前に必ず確認します。通信対戦の仕様変更、実装変更、Firebase Realtime Databaseルール変更を行う場合は、この文書もコードと同じコミットで更新します。

実装の挙動に関わる変更では、該当する画面遷移、公開・秘密データ、更新権限、切断・復帰時の扱いをこの文書へ反映します。仕様本文の変更が不要な修正であっても、仕様変更がないことを確認したうえで、この文書の最終更新日を同じコミットで更新します。

## 1. 用語

- **主催者**：通信対戦の部屋を作成したプレイヤー（ホスト）
- **参加者**：部屋番号・招待URL・QRコードから入室したプレイヤー（ゲスト）
- **親**：各ラウンドでカードを引き、親ワードを作成するゲーム内の役割
- **子**：各ラウンドで親ワードを推理するゲーム内の役割
- **切断**：再読み込み、ブラウザ・PWA終了、一時的な通信断など、明示的な退出を伴わない接続喪失
- **退出**：本人が右上メニューまたは復帰確認画面から明示的に宴を離れる操作

Firebaseがサーバーで、主催者・参加者の各端末はいずれもクライアントです。通信上の役割に「親・子」や「サーバー・クライアント」を使いません。

## 2. 基本方針

- 主催者と参加者の復帰方法は共通です。
- 切断と退出を分け、切断だけでは参加情報や宴を削除しません。
- 誰かが切断したら、時間制限なしで復帰を待ち、その間は全員のゲーム進行を停止します。
- 切断者が復帰したら、中断前と同じ宴・同じ進行状態から再開します。
- 誰か1人でも明示的に退出したら、その宴は終了します。
- 切断者を除外した続行、残り人数による続行、主催者移譲は実装しません。
- 通信固有の操作・同期・名前パネルを除き、1台版と通信版で共通するカード、ワード、候補番号、ボタンの表記・配置は共通仕様を優先する。差異を設ける場合は、仕様書に対象画面、理由、差異を明記する。


### 入口（宴の支度）

通信対戦開発版の通常入口は、タイトルの `はじめる` から開く1つの `宴の支度` 画面に統合する。旧来の「遊び方を選ぶ」「通信対戦」「宴を開く」「宴に参加する」は通常導線の独立画面として使用しない。通信エラー時などの復帰エラー画面は維持する。

- 共通見出しは `宴の支度`、説明文は `遊び方を選んで、宴の支度を整えてください。` とする。
- 上段の `1台で遊ぶ` と `通信対戦`、通信対戦時の `宴を開く` と `宴に参加する` は、既存のボタン表現を使う横並びのフォーム選択UIとする。上段のモード切替は、選択中を濃い緑の塗り・オレンジの太い内枠・明るい文字色、未選択を暗い緑灰色にする。通信対戦時の下段の役割選択は、選択中をオレンジ塗り、未選択を暗い緑灰色にして、上段とは別の見た目にする。
- モード切替は画面遷移ではなく同一画面内の表示切替とし、入力値は保持する。フォームを切り替えたときは、切り替え前フォームのエラー文だけを消す。
- 通常起動で最初に開くときは `1台で遊ぶ` を選択し、既存のプレイ人数、カードセット、ワードセット、推理時間の設定・保存・検証を維持する。`次へ` は客人の名乗りへ進み、客人の名乗りからの `戻る` は設定値を保ったまま宴の支度へ戻る。
- 通信対戦を初めて選ぶときは `宴を開く` を選択する。以後、同じ宴の支度画面内で1台版との切替を挟んでも、最後に選択していた `宴を開く`／`宴に参加する` を保持する。
- 通信対戦の客人名は1つの共通入力値とし、宴を開く・宴に参加するで同じ値を使う。保存済みの名前がない初期値は `客人` とする。宴を開く場合の推理時間の初期値は `2分` とする。
- 宴を開く・宴に参加するのFirebase処理、匿名認証、バリデーション、接続確認、ロールバックは変更しない。
- すべての入口フォーム下部は、左を `戻る`、右を主要操作（`次へ`、`部屋を作成`、`宴に参加する`）とする。戻るはタイトルへ戻る。
- 手動復帰可能な保存済み宴がある場合だけ、通信対戦の `宴を開く`／`宴に参加する` 選択UIの下、入力フォームの上に、横幅いっぱいのセカンダリーボタン `前の宴に復帰` を表示する。通信対戦を最初に選んだときは、このボタンの有無にかかわらず `宴を開く` を表示する。
- 招待URL・QRコードで開く場合は、宴の支度を `通信対戦`・`宴に参加する` 選択済み、部屋番号入力済みで直接開く。招待URL状態から `1台で遊ぶ` または `宴を開く` を明示的に選んだとき、または戻るを押したときはURLの `room` 指定を解除する。一度解除後は、宴に参加するへ戻しても招待状態を復元しない。
- 待機室の戻るでは既存の閉室・退出処理を完了してから宴の支度へ戻る。主催者は `通信対戦`・`宴を開く`、参加者は `通信対戦`・`宴に参加する` を選択した状態にする。入力済みの設定・部屋番号は保持してよいが、自動再参加はしない。

## 3. 名前パネルとメッセージバー

### 待機室

- 名前パネルとメッセージバーは表示しません。
- 「客人が揃うのを待っています」などをメッセージバーへ表示しません。
- 待機室の参加者一覧と入退室は、待機室固有の画面で扱います。



### 待機室の切断表示と開始条件

- 待機室の参加者一覧では、主催者を `○○（主催）` と表示する。
- 切断中の主催者は `○○（主催・切断）`、切断中の参加者は `○○（切断）` と表示する。復帰すれば切断表記を外す。
- 主催者だけが「宴を始める」を操作できる。
- 開始できるのは参加者が2〜6人で、かつ全員が接続中の場合だけとする。切断中の人が1人でもいる間はボタンを無効化する。
- 開始操作時もFirebaseから最新の部屋状態を再取得し、人数・主催者・待機状態・全員接続中を確認する。
- 主催者または参加者が切断中でも、新規参加は許可する。ただし全員が接続中になるまで開始はできない。
- 待機室での切断に時間制限や自動退出は設けない。
- 参加操作はFirebaseへの接続中にだけ受け付ける。オフラインのまま招待URL・QRコードを開いた場合は、待機室へ遷移させず参加画面で接続エラーを表示する。
- 待機室へ遷移する前に、参加情報・名前索引・接続状態がFirebase上で同じUIDとして登録済みであることを確認する。確認できない場合は参加情報を削除して参加画面へ戻す。

### ラウンド開始後

- 最初のラウンド画面から、名前パネルと直下のメッセージバーを画面上部へ固定表示します。
- 名前パネルとメッセージバーは、§10「確定したラウンド進行」で定義するすべての工程に共通するUIです。
- 名前パネルとメッセージバーの配置、高さ、重なり順、スクロール、表示文言の制御を修正する場合は、特定ページだけへ個別実装せず、共通処理としてラウンド開始後の全ページへ反映します。
- 今後ラウンド内のページを追加する場合も、明示的な除外仕様がない限り、この共通UIの対象へ含めます。
- 画面順、操作主体、各工程の遷移条件、実装済み範囲は§10を正本とする。§3ではこれらを重複して定義しない。
- 固定領域は上から、**各ページのタイトルと右側メニュー**、**名前パネル**、**メッセージバー**の順で表示する。
- 札選びではタイトルを `第一席　札選び` と表示する。以降のラウンド画面も `第○席　画面名` の形式とし、各ページのタイトルを固定領域の最上段に表示する。
- タイトルの右側には既存の「戦績」と「≡」メニューを表示する。
- 本文は固定領域の下から開始し、固定領域と重ねない。ページ全体はスクロールさせず、内容が画面高を超える場合だけ固定領域の下にある本文領域をスクロールする。本文が固定領域の裏へ入ることは許可しない。
- ラウンド中に遊び方を開いた場合は、戦績と同様に固定領域より前面に重なる画面として表示する。遊び方本文だけをスクロールし、下部の「戻る」ボタンは表示領域と端末の安全領域内で常に操作できるようにする。
- メッセージバーは1行表示とし、短い文言は静止表示します。
- 文言が表示幅を超える場合は、先頭を表示領域の中央付近から表示し、右から左へ自動スクロールします。
- 長文は適度な間隔を空けて同じ文言を連続配置し、表示が途切れる待ち時間を作らず繰り返します。
- 戦績やカード拡大などの重ね画面は、名前パネルとメッセージバーより前面に表示します。
- スワイプによる更新確認は独自実装しない。ブラウザ標準の挙動に委ねる。
- 通常時は現在の進行状況を表示します。
- 各工程のメッセージバー・カード周辺本文の文言は、この節の表を正本とする。

### 名前パネルの状態表示

ラウンド開始後の名前パネルは、上段を名前、中段を得点と親表示、下段を状態表示とする。親は上段の名前の前へ役割を付けず、中段の得点を左寄せ、`親`を右寄せで表示する。上段・中段は状態遷移では変更せず、状態に応じて変更するのは下段だけとする。

- 操作が必要な人の下段はオレンジで表示する。
- 操作を完了した人の下段は白で表示する。
- 操作待ちの人の下段は空白とする。
- 状態の対象でない人の下段は空白とする。
- 明示的に退席した人は、接続状態にかかわらず下段を `退席` の白で最優先表示する。
- 切断中の人は、現在の進行状態にかかわらず下段を `切断中` の赤で表示する。復帰時は、その時点の工程に対応する下段表示へ戻す。

| 画面 | 親の下段 | 子の下段 | 色 |
|---|---|---|---|
| 札選び | `札選び中` | 空白 | `札選び中` はオレンジ。 |
| 親のひそめごと | `ひそめ中` | 空白 | `ひそめ中` はオレンジ。 |
| 宴の推理 | 空白 | `推理中` → `推理完了` | `推理中` はオレンジ、`推理完了` は白。 |
| 推理結果の記帳 | 空白 | `回答中` → `完了` | `回答中` はオレンジ、`完了` は白。 |
| ひそめごと開帳 | `開帳` | 空白 | `開帳` はオレンジ。 |
| 宴の顛末 | 空白 → `得点確認` | 空白 | 画面遷移直後は全員空白。ルーレット終了後の `得点確認` はオレンジ。 |
| 得点処理 | `次の席へ` | 空白 | `次の席へ` はオレンジ。 |
| 勝利画面 | `確認中` → `退席` / `再宴希望` | `確認中` → `退席` / `再宴希望` | `確認中` はオレンジ、`退席` と `再宴希望` は白。 |

### メッセージバーとカード周辺本文

ラウンド開始後の画面では、カード上に文章を置かない。進行状況・全員へ伝える案内は固定ヘッダー内のメッセージバーへ表示し、本人だけに必要な補足がある場合だけカード周辺本文を表示する。本文がない画面でも、カード、候補、操作ボタンなどの画面要素は通常どおり表示する。

- `○○さん` は、そのラウンドの親の名前を表す。
- 切断中は名前パネルの下段に「切断中」と表示する。メッセージバーには切断情報を重複表示せず、その画面本来の進行メッセージを維持する。切断中は進行操作だけを停止する。宴終了時は、宴終了メッセージを最優先とする。
- 宴の推理では、親も会話で子の質問に受け答えする。親・子ともに同じメッセージバー文言を表示する。
- カード周辺本文の配置は、対応する1台版の既存画面構成を維持する。通信版だけの都合でカード位置・本文位置を変更しない。
- 操作主体でないプレイヤーには、その工程の入力欄・候補選択・進行ボタンを表示しない。無効化した待機用ボタンも表示しない。ただし札選びの子には、操作不可の山札だけを表示する。

| 画面 | 親のメッセージバー | 子のメッセージバー | 親のカード周辺本文 | 子のカード周辺本文 |
|---|---|---|---|---|
| 札選び | `○○さん、伏せ札の山から1枚引いてください。` | `○○さんが札を選んでいます。` | なし | なし |
| 親のひそめごと | `公式ワード3つを確認し、親ワードをひそめてください。` | `○○さんがひそめごとを考えています。` | `4つ目にあなたのワードを入力してください。` | なし |
| 宴の推理 | `子が親ワードを推理しています。高貴に振る舞いましょう。` | `会話しながら、親がひそめたワードを推理してください。` | なし | `心が決まりましたら「推理完了」を押してください。` |
| 推理結果の記帳 | `子が推理結果を記帳しています。` | `親ワードだと思う言葉を1つ選んでください。` | なし | `選択が終わりましたら「決定」を押してください。` |
| ひそめごと開帳 | `全員の記帳が完了しました。○○さん、ひそめごとを開帳してください。` | `全員の記帳が完了しました。○○さん、ひそめごとを開帳してください。` | なし | なし |
| 宴の顛末 | ルーレット中：`ひそめごとを開帳しています。`<br>終了後：`○○さん、得点を確認してください。` | ルーレット中：`ひそめごとを開帳しています。`<br>終了後：`○○さん、得点を確認してください。` | なし | なし |
| 得点処理 | `得点が反映されました。○○さん、次の席へ進んでください。` | `得点が反映されました。○○さん、次の席へ進んでください。` | なし | なし |
| 勝利画面 | `宴の結果をご確認ください。` | `宴の結果をご確認ください。` | `「タイトルへ」を選ぶと宴を終了します。全員が「もう一度遊ぶ」を選ぶと、第一席から再開します。` | `「タイトルへ」を選ぶと宴を終了します。全員が「もう一度遊ぶ」を選ぶと、第一席から再開します。` |

### 勝利画面での退席

勝利画面で誰か1人が `タイトルへ` を押した場合は、その本人だけを通信対戦画面へ戻す。残っているプレイヤーは勝利画面を維持し、通信対戦画面へ自動遷移させない。

- `タイトルへ` を押した本人の名前パネル下段は `退席` とする。
- 残っているプレイヤーは、名前パネル、得点、勝利画面を維持する。
- 残っているプレイヤーのメッセージバーには、`○○が退出したため、宴はお開きとなります。右上メニューの「退出」から退出してください。` を表示する。
- 残っているプレイヤーは、右上メニューの `退出` で通信対戦画面へ戻る。
- 宴終了後は、勝利画面の「タイトルへ」「もう一度遊ぶ」を含むゲーム進行操作を利用できない。


## 4. 切断中

残っているプレイヤーの画面：

- 現在のラウンド画面を維持します。
- 回答、決定、次画面への遷移など、ゲームを進める操作を停止します。
- 切断者は名前パネル下段の `切断中` で表示する。通常の進行メッセージはメッセージバーに維持し、切断者・復帰待ちの文言へは切り替えない。
- 復帰待ちの時間制限は設けません。
- 右上メニューの退出は利用できます。

## 5. 切断者の復帰

端末へ少なくとも以下を保存します。

- 部屋番号
- Firebase UID
- プレイヤー名
- 通信上の役割（主催者／参加者）
- 参加していた宴の識別情報

保存済みの宴は、部屋の存在、同じUIDの参加情報、保存した主催者／参加者の役割、宴の識別情報をFirebaseで照合して扱います。起動時の動作は次のとおりです。

| 起動条件 | 動作 |
|---|---|
| 招待URL・QRコードで開き、招待先と保存済みの宴が異なる | 保存済みの宴に関する確認を出さず、招待先の参加画面へ進む。 |
| 招待URL・QRコードで開き、招待先と保存済みの宴が同じ | 確認なしでその宴へ自動復帰する。 |
| 通常起動で、保存済みの宴に誰か1人でも接続中 | 確認なしで前の宴へ自動復帰する。 |
| 通常起動で、保存済みの宴が全員切断中 | タイトルへ進む。復帰情報は保持し、宴の支度で通信対戦を選んだときだけ `前の宴に復帰` を表示する。 |
| 保存済みの宴が終了済み、または閉室済み | 復帰情報を自動削除し、確認を出さずタイトルまたは招待先へ進む。 |

復帰成功時は、本人をオンラインへ戻し、Firebaseの進行状態から中断前の画面を復元します。他端末の切断表示を解除し、全員がオンラインへ戻ったらゲーム進行を再開します。

照合や通信状態の確認に失敗した場合は、部屋が削除・終了したとは判断せず、端末の復帰情報を削除しません。通常起動時は復帰確認を出さずタイトルへ進みます。

起動時の非同期復帰判定が完了した時点で、ユーザーが初期タイトル画面から操作により別画面へ遷移済みの場合は、通常のタイトル表示で現在画面を上書きしません。復帰対象がある場合の自動復帰と、招待URL・QRコードでの参加画面表示は従来どおり実行します。
## 6. 明示的な退出

接続中の右上メニューからの退出と、復帰確認画面からの退出は同じ意味です。

- 退出前に「退出すると全員の宴が終了する」ことを確認します。
- 退出確定後、本人の退出情報をFirebaseへ記録します。
- 本人の端末から復帰情報を削除します。
- 退出した本人は通信対戦画面へ戻ります。
- 宴を終了状態とし、残っている全員へ通知します。
- 残っているプレイヤーの名前パネルでは、退出した本人の下段を `退席` と表示します。

確認文言例（未確定）：

`退出すると、この宴は全員終了となります。退出しますか？`

## 7. 宴終了後の残存画面

誰かが退出しても、残っている人を通信対戦画面へ自動遷移させません。

- 現在のラウンド画面、名前パネル、得点を維持します。
- メッセージバーへ終了理由と各自の退出案内を表示します。
- ゲームを進める操作は無効化します。
- 戦績、メニュー、遊び方、カード拡大など、振り返りに必要な閲覧操作は利用できます。
- 各自が確認後、右上メニューの退出から通信対戦画面へ戻ります。
- 同時退出時は、最初に記録された退出者を終了理由として表示します。

文言例（未確定）：

`○○が退出したため、宴はお開きとなります。右上メニューの「退出」から退出してください。`

| 操作 | 宴終了後 |
|---|---|
| 戦績・メニュー・遊び方 | 利用可 |
| カードの拡大・確認 | 利用可 |
| 回答・決定 | 利用不可 |
| 次画面・次ラウンドへの進行 | 利用不可 |
| 退出 | 利用可 |

## 7-1. 宴の顛末における切断例外

通常は、誰かが切断した場合にゲーム進行操作を停止します。ただし、`宴の顛末` で共有ルーレットが開始された後は、ルーレット演出だけを次の例外として扱います。

- ルーレット開始後に切断者が出ても、演出自体は停止しません。
- 接続中の端末では、共有 `roulettePlan` とFirebaseサーバー時刻に従って最後まで再生します。
- ルーレット終了後は、親ワード確定と得点変動予告まで表示します。
- 切断者が復帰した場合は、`serverNow() - revealCompletedAt` から現在位置を再計算し、同じ `roulettePlan` を使って途中状態を復元します。
- すでに終了時刻を過ぎている場合は、ルーレットを最初から再生せず、完成済み結果を表示します。
- 切断中は親の「得点を確認」だけ操作不可とします。
- 全員が復帰すると、追加操作なしで親の「得点を確認」を操作可能へ戻します。
- メッセージバーを切断専用文言へ変更しません。
- 切断状態は名前パネルの「切断中」で表示します。


## 7-2. `score` の正式な得点処理

親が宴の顛末で「得点を確認」を押すと、`round.phase = score` と全プレイヤーの実得点をFirebase Realtime Databaseの同一原子的更新で保存する。現在phaseが `result` の場合だけ実行でき、再クリック・再読み込み・復帰では再加点しない。

- 得点計算は1台版 `game-rules.js` の `scoreRound()` を使用する。2人対戦では子の正解だけを+1とし、親の加減点は行わない。3人以上では全員不正解で親+1、全員正解で子全員+1かつ親-1（下限0）、一部正解で正解した子だけ+1とする。
- `score` では既存の `[data-screen="scores"]` を表示し、タイトルは `第○席　得点の記録` とする。全端末に今回の結果とFirebaseへ反映済みの全員の現在得点を表示する。
- メッセージバーは全員共通で `得点が反映されました。○○さん、次の席へ進んでください。` とする。名前パネルは親だけをオレンジの `次の席へ` とし、子は空白とする。退席・切断中の優先順位は共通仕様を維持する。
- 親だけに `次の席へ` を表示する。全員接続中、宴が継続中、勝者がいない場合だけ操作可能とし、切断中は得点画面と得点を維持したままボタンだけを無効化する。復帰時は自動で再有効化する。
- いずれかが5ポイント以上に到達した場合は得点画面のまま次ラウンドへの進行を停止する。正式な勝利画面、戦績確定、再宴は未実装である。
- `次の席へ` は現在の `room.seats` の次席を親にし、`round.number` を+1、`round.phase` を `draw` にする。`usedCardIds` は維持し、カード・公開ワード・回答・ルーレット・時刻など前ラウンド固有の公開データは新ラウンドへ持ち越さない。旧ラウンドの `roomSecrets`、`roomProgress`、`roomAnswers` は削除しない。
- 得点反映と次席遷移のRulesでは `numChildren()` を使用しない。2〜6人の人数と次親は `seats/2`〜`seats/5` の存在で判定し、全員正解・全員不正解は、親以外の存在する各席UIDが `publicAnswers/{parentCandidateIndex}` に `true` を持つかで判定する。
- `result → score` と `score → draw` のRules上の進行権限は `hostUid` ではなく、現在の `parentUid` 本人だけに与える。


## 8. 切断中に宴が終了した場合

切断中に別のプレイヤーが退出した場合、次回起動時に通信対戦画面へ直接戻しません。

- 終了した宴のラウンド画面を復元します。
- 終了メッセージを表示します。
- 戦績・遊び方・カードなどを確認できます。
- ゲーム進行はできません。
- 本人が右上メニューから退出した後、復帰情報を削除して通信対戦画面へ戻ります。

## 9. メッセージバーの優先順位

1. 宴終了
2. 通常の進行状況

切断中は名前パネル下段の表示だけで伝え、メッセージバーの優先順位には含めない。

正式文言は各画面の実装時に確定します。

## 10. 確定したラウンド進行

この節は通信対戦版の確定仕様です。待機室から、札選び、親のひそめごと、宴の推理、推理結果の記帳、ひそめごと開帳、宴の顛末、共有ルーレット、実得点の反映、得点処理、次席への親交代、次ラウンドの札選びまでを実装対象とする。戦績確定、正式な勝利画面、再宴は今回の対象外とする。

1. **札選び**（操作：そのラウンドの親）：開始時の公開部屋には `round.number` と `round.phase: draw` を保存する。使用済みカードがない開始時は `round.usedCardIds` を保存しない。親だけが山札からカードを引き、`round.phase` を `draw` から `parent-word` へ更新するときに、`round.cardId`、`round.cardImage`、`round.usedCardIds` を保存する。`round.cardId` は数値、`round.usedCardIds` の子キーは文字列として照合する。親の公開書込み先は `rooms/{roomId}/round` に限定する。カードを引いたら親のひそめごとへ進む。切断者がいる間は誰も操作できない。
2. **親のひそめごと**（操作：そのラウンドの親）：カード画像は全員へ公開する。公式ワード3個は親だけが見る。子にはカードと待機表示だけを見せる。子は、親がどこに注目して親ワードを考えているかを想像したり、会話で親へプレッシャーをかけたりできる。親ワード確定前に、公式ワード3個を子の端末へ送信・保存・表示しない。親は親ワードを入力して「ひそめる」で確定し、直ちに宴の推理へ進める。「ひそめる」の下には「もう一度引く」を置く。これを押すと札選びへ戻り、引いた札を使用済みのまま別の札を引く。
3. **宴の推理**（操作：子のみ）：親ワード確定時に、公式ワード3個と親ワード1個をシャッフルして全員へ公開し、独立したお披露目画面を挟まず宴の推理画面へ遷移する。同時に、部屋作成時に設定した推理時間のカウントダウンを開始する。全員で会話しながら推理する。子はタイムアップを待たず「推理完了」を選べる。名前パネルには親・各子の推理状態を表示する。全員の子が推理完了、またはタイムアップで推理結果の記帳へ進む。親はこの工程の進行操作をしない。この工程は実装済みである。
4. **推理結果の記帳**（操作：子のみ）：子は各端末で同時に親ワードだと思う候補を1つ選ぶ。回答時間は無制限とし、1台版のように順番に記帳する方式にはしない。名前パネルには子ごとに「回答中」「完了」を表示する。全員の子が回答完了するまで、他の子の回答は公開しない。新しいラウンドで未回答の子は候補未選択・決定不可の状態から開始する。現在ラウンドのFirebase保存済み回答がある復帰時だけ、その候補を回答済みとして表示する。
5. **ひそめごと開帳**（操作：そのラウンドの親）：全員の子が回答を完了したら、親が各子の回答を読み取り、`round.publicAnswers` に候補番号ごとのUID集合を保存し、`round.phase` を `reveal` に更新する。この更新を検知した全端末が自動でひそめごと開帳画面へ進む。画面にはカード、推理時と同じ順番の4ワード、各ワードの票数と選択者名を表示する。候補番号、親ワードの位置、正誤、得点はこの時点では表示しない。親だけに「ひそめごと開帳」ボタンを表示し、子には待機用ボタンを表示しない。親がボタンを押すと、秘密領域の `parentCandidateIndex` と一致する `round.parentCandidateIndex`、共有用の `round.roulettePlan`、開始時刻 `round.revealCompletedAt` を保存し、`round.phase` を `result` に更新する。全端末が `宴の顛末` へ自動遷移する。
6. **宴の顛末**（操作：そのラウンドの親）：`round.roulettePlan` と `round.revealCompletedAt` を使い、Firebaseサーバー時刻を基準に既存1台版と同じルーレットを全端末で同期再生する。全員接続中かつルーレット終了後に親が「得点を確認」を押すと、公開回答と正解候補から計算した実得点と `round.phase = score` を同一原子的更新で保存する。
7. **得点処理**（操作：そのラウンドの親）：反映済みの現在得点を全端末に表示する。勝者がいなければ親が「次の席へ」を押し、席順の次席を親にして、ラウンド番号を+1、phaseを `draw` にした新ラウンドを原子的に保存する。
8. **勝利画面**（勝利ポイント到達時、操作：全員）：全員が勝利演出を見る。「タイトルへ」と「もう一度遊ぶ」を表示する。「タイトルへ」を押した本人だけを通信対戦画面へ戻す。残っているプレイヤーは勝利画面を維持し、メッセージバーの終了案内を確認後、右上メニューの「退出」から退出する。全員が「もう一度遊ぶ」を押したらポイントをリセットし、第一席から開始する。

ラウンド中は、すべての工程で画面上部に名前パネルとメッセージバーを常時表示する。

### 共通UIと共有タイマー

- 4ワードを表示する画面では、候補番号を `1`〜`4` とする。番号は各候補の左端の固定位置に表示し、句点を付けない。ワードは候補内で中央揃えにする。この構造・表記は1台版と通信版で共通とする。
- 推理時間、ルーレットなど全端末で同じ期限を扱う工程は、Firebase Realtime Databaseのサーバー時刻を正本とする。開始・期限はサーバー時刻で保存し、各端末の表示は `/.info/serverTimeOffset` で端末時計を補正して計算する。端末ローカルの `Date.now()` だけを共有期限の基準にしてはならない。

### 秘密情報

- 親のひそめごと画面では、公式ワード3個を子の端末へ送信・保存・表示しない。
- 公式ワード3個、親ワード、親ワードと候補の対応情報は、全員が購読する `rooms/{roomId}` に保存しない。
- 第一席では、親専用データを `roomSecrets/{roomId}/rounds/{roundNumber}/{parentUid}` に保存する。親本人だけがread/writeできるFirebaseルールとする。
- 宴の推理へ遷移するときに4ワードを全員へ公開するが、どの候補が親ワードかを対応づける情報は `roomSecrets` の親専用データとして保持する。全員が購読する `rooms/{roomId}` には、この対応情報を保存しない。
- 子の回答確定と開帳前に、親ワードの対応情報・他の子の回答・正誤判定を子へ送信・保存・表示しない。
- 推理完了・回答完了の状態は `roomProgress/{roomId}/rounds/{roundNumber}` に本人単位の真偽値だけを保存する。子の回答は `roomAnswers/{roomId}/rounds/{roundNumber}/{uid}` に保存し、本人とそのラウンドの親だけが読めるルールとする。
- 全子回答完了後、親だけが `roomAnswers/{roomId}/rounds/{roundNumber}` を読み取り、候補番号の対応を `rooms/{roomId}/round/publicAnswers` として公開する。公開用データには親ワードの正解位置を含めない。
- `round.publicAnswers` の公開と `round.phase = reveal` への更新は同一の更新で行う。開帳ボタン押下後は `round.phase = result` と `parentCandidateIndex`、`roulettePlan`、`revealCompletedAt` を同一更新で保存する。宴の顛末で親が「得点を確認」を押すと、得点と `round.phase = score` を同一更新で保存する。
- 画面上の非表示だけでなく、Firebaseのデータ配置とルールで閲覧権限を分離する。

## 11. 復元する進行状態

端末内の画面番号だけに依存せず、Firebase上の宴状態を正本とします。少なくとも以下を段階的に同期します。

- ラウンド番号、現在工程、席順、現在の親
- 使用中カード、公式ワード、親ワード、公開4ワードと表示順
- 回答状況・回答、得点、戦績
- 宴終了状態と退出者
- 各プレイヤーの接続状態

秘密情報は、その工程で閲覧権限がある端末だけに表示します。具体的なデータ構造とFirebase Rules全文は、本書および [`firebase-rules.json`](../firebase-rules.json) に記載します。

## 12. 実装順序

1. 復帰基盤：端末保存、接続状態、切断と退出の区別、現在完成している札選びまでの復帰
2. 1ラウンドの正常系を最後まで完成
3. 各工程をFirebase状態から復元
4. 全ラウンド画面へ切断中の停止とメッセージバーを適用
5. 確定したデータ構造に合わせてFirebaseルールを更新

## 13. Firebaseルール

現在の実装範囲（札選びから、`result → score` の得点反映、`score → draw` の親交代と次ラウンド開始まで）に必要なRealtime Database Rulesを管理する。Firebase Consoleへの反映は別操作で行う。

Firebase Rulesの正本は、ルートの [`firebase-rules.json`](../firebase-rules.json) だけとする。Rulesを変更する実装では、同じコミットでルートの `firebase-rules.json` を更新し、この仕様書内のリンクが最新ファイルを参照する状態にする。実装完了の回答本文にはRules全文を掲載せず、更新済みの [`firebase-rules.json`](../firebase-rules.json) へのリンクを記載する。Firebase Consoleへ貼り付ける場合は、リンク先ファイルの内容を全文コピーする。要約・差分だけをRulesの正本として扱ってはならない。`docs/firebase-rules.json` は作成・更新せず、Rules全文の二重管理を行わない。

現在の `publicAnswers` は「候補番号 → UID集合」形式です。Rulesは、公開された各UIDが参加中の子であり、保存済み回答の候補番号と一致すること、候補番号が0〜3であることを検証します。一方、Realtime Database Rulesには動的な子キー集合を反復して比較する機能がないため、この形式のままでは「全子が必ず1回だけ含まれること」をRulesだけで完全には保証できません。これをRulesで完全保証する必要が生じた場合は、UIDをキーにした公開結果（例：`publicAnswersByUid/$uid`）へデータ構造を変更し、UIDごとの一意性と回答人数を検証する別仕様を定めます。今回の実装ではデータ構造とRulesを変更しません。
